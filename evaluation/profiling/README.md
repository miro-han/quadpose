# Phase II SAM 2.1 처리 시간과 LK 비교

기존 CUDA `.venv`, SAM 2.1 Hiera Tiny 가중치, 동봉 영상으로 실행합니다. Phase I 코드와 결과는 그대로 사용했습니다. 이 스크립트의 임시 JPEG·PNG·MP4와 CUDA 트레이스는 결과 폴더 옆의 임시 디렉터리에서 생성 후 정리합니다.

## 재현

프로젝트 루트의 PowerShell에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe .\evaluation\profiling\profile_pipeline.py --repeats 3 --kernel-trace
.\.venv\Scripts\python.exe .\evaluation\profiling\profile_pipeline.py --e2e-only fp32 --output .\evaluation\profiling\results\e2e_fp32.json
.\.venv\Scripts\python.exe .\evaluation\profiling\profile_pipeline.py --e2e-only fp16 --output .\evaluation\profiling\results\e2e_fp16.json
```

기본 입력은 `WIN_20261124_20_05_34_Pro.mp4` 프레임 0–29와 Phase I의 첫 프레임 박스입니다. `--video`, `--frames`, `--box x0 y0 x1 y1`로 입력을 바꿀 수 있습니다. 폴더 처리 상한은 120프레임입니다. VRAM이 부족하면 프레임 범위를 줄일 수 있습니다. `--output`으로 기존 측정과 다른 파일에 저장할 수 있습니다.

## 측정 방법

- 원본 OpenCV 디코딩, Phase I 호환 JPEG 인코딩, JPEG 파일 쓰기, 공식 JPEG 읽기·디코딩·리사이즈·정규화(1024×1024)를 CPU 구간으로 계측합니다. 마지막 묶음에는 파일 읽기가 포함됩니다.
- 공식 SAM 비디오 예측기의 입력 로더에 미리 처리한 텐서를 전달합니다. 로더에 들어가기 전에 H2D 전송을 측정합니다. GPU 상주 방식에서 이미지와 추적 상태는 GPU에 놓고 초기화(첫 프레임 백본), 박스 프롬프트, 전파를 측정합니다. 마스크 임계값·유한성 검사와 D2H 전송은 전파 타이머 밖에 있습니다.
- CUDA Event는 같은 계산 스트림의 계측 구간을 나타내며, 장치가 다음 명령 제출을 기다리는 구간도 포함합니다. 동기화한 호스트 경과 시간도 저장합니다. `--kernel-trace`는 추가 FP32 실행에서 가능한 경우 GPU 커널·복사·메모리 초기화 이벤트를 수집합니다. 커널 시간은 구간들의 합집합입니다. GPU 활동 사이의 공백에는 런타임·커널 제출·의존성 대기가 섞일 수 있습니다.
- 이미지와 추적 상태를 CPU에 둔 FP32 방식에서는 CPU↔GPU 전송 비용이 전파 타이머 안에 들어갑니다. GPU 상주 FP32·오프로딩 FP32·FP16·BF16의 순서를 반복마다 순환시키며, 상주 모드의 입력 텐서는 각 실행이 끝나면 GPU에서 해제합니다. 입출력 병행 실행이나 UI 이벤트 루프는 이 실험에 포함하지 않았습니다.
- Phase I의 시각화 함수로 오버레이·선택 에지 계산을 측정합니다. PNG CPU 인코딩과 PNG/JSON 파일 쓰기는 분리했습니다. OpenCV MP4 인코딩과 파일 쓰기는 한 타이머에서 측정하고, 디코딩 검증은 타이머 밖에서 수행합니다. 파일 쓰기 시간에는 운영체제 캐시가 포함되며 디스크 동기화까지 기다리는 `fsync`는 사용하지 않았습니다.
- FP32는 TF32를 끕니다. FP16/BF16은 PyTorch CUDA AMP로 선택된 연산을 변환합니다. AMP가 FP32로 실행하는 연산과 SAM이 자체적으로 BF16으로 보관하는 메모리 상태가 남습니다. 모드 전체가 미지원이거나 실행 오류가 나면 JSON에 사유를 기록합니다. 모드 간 자동 재시도는 없습니다. 마스크의 `>0` 이진화 결과를 FP32와 비교하고, 출력 로짓의 `NaN`/`Inf` 및 빈 마스크도 기록합니다.
- `--e2e-only`는 별도 프로세스에서 원본 영상을 여는 시점부터 마스크·에지 PNG 및 MP4 저장이 끝날 때까지 벽시계 시간으로 잽니다. 이 구간에는 모델 로드도 포함합니다. Python 모듈 가져오기와 저장 영상 재디코딩 검증은 계측 밖입니다. 영상 파일 30프레임의 오프라인 시간입니다.

## 초기 SAM + LK 구성

`SamMasks.predict(..., propagate=False)`는 첫 프레임 마스크를 생성합니다. `MaskTracker`의 `initialize(frame, mask)`와 `update(frame)`가 경량 추적기의 교체 경계입니다. 후단은 원본 좌표계의 이진 마스크와 결과 상태를 받습니다. `SamMasks.predict(..., propagate=True)`는 동일한 첫 박스를 받아 매 프레임 SAM 전파를 수행하는 비교 경로입니다. 후단은 두 경로의 마스크를 같은 방식으로 평가하거나 저장할 수 있습니다.

LK 구현은 현재 마스크에서 Shi–Tomasi 특징을 찾고, 양방향 피라미드 LK와 RANSAC 호모그래피를 거쳐 이전 마스크를 워핑합니다. 특징 수, 순방향·역방향 오차, 인라이어 비율과 공간 분포, 면적 변화로 업데이트를 거절합니다. 실패한 프레임의 `mask`는 `None`이며, 새 마스크로 `initialize`를 호출할 때까지 `needs_reinitialization`을 반환합니다. 처리 루프에서 그 프레임의 신뢰할 수 있는 박스나 마스크를 확보하면 재초기화할 수 있습니다. 한 장의 호모그래피는 주로 평면 변화에 적합하므로 강한 가림, 무늬가 부족한 표면, 새로 보이는 면과 큰 3D 회전에는 재초기화가 필요할 수 있습니다.

실시간 통합에서는 카메라별 추적기 인스턴스와 입력 프레임 ID·타임스탬프를 유지합니다. SAM 재시드는 같은 카메라와 요청 프레임으로 연결하고, 만료된 결과는 최신 프레임에 합치기 전에 검증해야 합니다. 초기 SAM + LK 경로의 유효성 판단과 재시드 시점을 매 프레임 SAM 경로와 같은 영상 및 주석에서 비교할 수 있습니다. 이 프로토타입은 단일 동봉 영상에서 수동 박스로 초기화한 결과이며 재시드용 검출기를 구현하지 않았습니다.

### 초기 SAM + LK

첫 마스크는 이미 전처리한 한 프레임을 GPU에 올리는 시점부터 CPU로 마스크를 받기까지 계측한 단계의 합이 **120.8 ms**였습니다. LK는 원본 해상도에서 **20/30 프레임**의 마스크를 반환했습니다. 첫 프레임을 제외한 유효 업데이트 19회의 중앙값은 **85.44 ms**였습니다. 0번부터 세었을 때 20번 프레임에서 일관된 대응점 46개 중 인라이어가 26개로 허용 비율 65%에 미달했습니다. 나머지 9프레임은 재초기화가 필요한 상태였습니다. 유효한 20프레임에서 SAM FP32 마스크와 IoU는 평균 **0.985638**, 최저 **0.971720**이었습니다.

추가 합성 점무늬 영상에서 프레임당 가로 3픽셀·세로 2픽셀씩 이동시킨 10회 업데이트의 최저 IoU는 **1.0**이었습니다. 검은 화면 주입 시 무효 상태를 반환했고, 새 마스크로 명시적으로 재초기화할 수 있었습니다. 실측 영상의 IoU는 SAM 기준의 출력 일치도입니다. 실제 물체 윤곽 정확도와 네 카메라의 실시간 지연은 별도 주석과 동시 취득 실험이 필요합니다.
