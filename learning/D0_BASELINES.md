# Layout A 독립 기하 기준선과 Oracle 제어군

이 실행은 세 학습 트랙이 비교할 Layout A 기하 기준선을 만든다. [D0 계약](DATASETS.md)의 독립 `lockbox`에서 16개 궤적, 192프레임을 각 방법에 같은 순서로 제공했다. 기존 테스트의 수치는 회귀와 과거 비교에 사용하며, 이번 수치의 분모에 합치지 않았다. 카메라는 `−Y,+X,+Z,(+,-,+)`를 사용하고 알려진 모형 치수 및 보정값을 받았다. 모든 추적기는 각자 이전 유효 자세만 다음 초기값으로 썼다.

## 비교 방법

| 방법 | 동작 |
| --- | --- |
| All / Best | 기존 전체 관측 공동 최적화와 최소 내부 RMS의 3개 카메라 후보 |
| Cross / Cross+Verify / Cross+Alternating | 기존 교차 검증 선택, 교차 선택 후 대응 제거·재적합, 제한된 교차 선택 후 반복 재적합 |
| Recovery / Adaptive | 기존 전체 복구 정책과 별도 비학습 탐색 범위 적응 정책 |
| GT 대응 | 검출에서 실제 물리 ID가 알려진 코너·에지만 사용할 수 있다. 관측 잡음, 외부 오차와 시차는 그대로다. |
| GT 가설 선택 | 추정 대응으로 구성한 기존 3-of-4 후보 가운데 현재 정답에 가장 가까운 유효 후보를 고른다. 비용은 `(위치 mm/20)^2 + (회전 °/8)^2`다. 후보의 자세와 대응은 바꾸지 않는다. |
| GT 관측 가중치 | 결함을 주입한 카메라의 전체 가중치를 0, 나머지를 1로 두는 이진 제어다. 다른 카메라의 물리 ID와 연속 가중치는 알려 주지 않는다. |
| GT 초기화 | 프레임 0의 자세만 정확히 주고 그 다음부터 일반 All 추적을 한다. 뒤 프레임의 정답을 받아 다시 초기화하지 않는다. |

GT를 쓰는 네 행은 외부 정답이 있는 디버깅 제어군이다. 각 행은 서로 다른 병목을 제거하므로 하나의 성능 상한으로 합치지 않는다. 에지 F1은 참 검출이 하나 이상 있는 `(카메라, 물리 ID)`를 재현율 분모로 하고, 수용한 같은 수의 `(카메라, 모델 ID)`를 정밀도 분모로 쓴다. 쌍 정확도는 두 카메라가 같은 ID를 주장한 경우 실제 두 관측 모두 해당 에지인지 평가한다. 측정 성공은 20 mm 및 8° 이내에서 실제 유효 측정을 한 경우다. 자세 오차에 유지·예측 상태를 포함하며, 거부 후에는 기록한 포즈가 없으면 마지막 유효 측정을 사용한다. 지연은 합성 입력을 메모리에 구성한 후부터 자세 반환까지의 CPU 벽시계 시간이다.

```powershell
python -B -m evaluation.resource_limits --threads 1 --memory-gib 3 learning.d0_baselines --output learning/results/stage1_d0_replay
```

이 실행은 OpenCV 스레드를 1개로 고정하고 OpenCL을 끈다. 합성 검출 생성, 녹화·영상 디코딩·분할 및 CSV 저장 시간은 제외한다. [프레임 원자료](results/stage1_d0/frames.csv) · [조건별 집계](results/stage1_d0/summary.csv) · [실행 설정](results/stage1_d0/manifest.json)
