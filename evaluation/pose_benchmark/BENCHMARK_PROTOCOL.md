# Phase IV 고정 벤치마크 설계

이 실험은 검출된 영상의 2D 코너·선분 후보에서 시작한다. 모델은 실측 치수가 알려진 직육면체를 가정한다. 보정값과 물체 치수는 알고리즘 입력에 들어가고, 실제 자세와 물리 ID는 시뮬레이터·채점기에서만 사용한다. Oracle은 물리 ID를 알려 주는 별도의 대조군이다. 실물 영상의 검출 또는 실시간 캡처 검증은 포함하지 않는다.

## 자료와 실행 순서

[동결 설정](benchmark_config.json)의 개발 시드는 41011·41039, 독립 시험 시드는 53003·53017이다. 개발 자료에서 대응, 반복, 선택 및 복구 정책을 비교했고, 동일한 정책·문턱값으로 독립 시험을 실행한다. 기존 Phase II·III 알고리즘과 결과 파일을 읽기 전용으로 보존한다. 주 실험은 실제 꼭짓점 거리의 `x-y+z+`, `x-y-z+`, `x-y+z-` 세 후보를 사용한다. `x-y+z-`는 과거 B와 동일하다. 과거 A `x+y-z+`는 이번 현장 후보군에 포함하지 않았다. 각 조건은 18프레임이며 프레임 시각 간격은 합성 30 Hz이다. 결함 창은 0부터 번호를 매겼을 때 `[5,12)`다. 정상 및 자기 가림 조건은 전체 구간을 활성으로 본다.

카메라·물체·노이즈의 결합을 먼저 메모리에 구성하고 모든 방법이 동일한 검출 배열을 받도록 했다. 각 방법은 처음에 정답에 잡음을 준 **한 번의 거친 외부 초기 자세**를 받는다. 그 후 자기 방법이 보낸 마지막 유효 측정값 또는 그 방법 자체의 복구 상태만 사용한다. 잘못된 자세도 방법이 유효라고 판정하면 다음 프레임으로 전달한다. 이를 통해 오답이 다음 대응을 오염시키는 과정까지 평가한다. 거부·예측은 측정 이력을 갱신하지 않는다. 모든 검출이 사라진 구간은 복구 검사에 별도로 사용한다.

| 조건 | 활성 구간 입력 |
| --- | --- |
| 정상 / 자기 가림 | 정상 잡음·누락. 자기 가림 조건에서는 더 크게 기울이며 볼록 상자 면에 의해 실제 가려진 특징을 삭제한다. |
| 외부 가림 | 반지름 85 mm 손 구와 시선이 만나는 부분을 제거하고 가장 긴 가시 구간을 검출 후보로 남긴다. |
| 잘못된 에지 ID | 두 카메라에서 다수의 참 선분을 빼고 다른 작은 이동·회전을 한 실루엣의 선분을 주입한다. 검출은 무라벨 자료이며, 채점할 때 유령 선분은 `−1`이다. |
| 코너 누락 / 분절 | 모든 코너를 제거하거나 선분 하나를 간격이 있는 두 조각으로 나누고 순서를 섞는다. 같은 참 에지의 조각은 채점용 물리 ID를 공유한다. |
| 단일 / 복수 카메라 오류 | 한 대 / 두 대의 관측을 비운다. `one_view`는 한 대만 남긴다. |
| 보정 / 시각 오류 | 한 카메라의 생성 외부 보정을 이동·회전시키거나, 해당 카메라만 4프레임 이전 자세를 보게 한다. 알고리즘에는 기존 보정과 공통 타임스탬프를 전달한다. |
| 급회전 / 재획득 | 급회전은 활성 창에서 프레임당 최대 약 0.55 rad 회전 증분을 추가한다. 재획득은 활성 창의 모든 관측을 잃고, 물체가 회전한 후 다시 관측된다. |
| 복합 결함 | 손·분절·유령 선을 섞고, 한 카메라의 보정을 틀리게 하며 다른 카메라 한 대를 끊는다. 같은 시간에 물체가 회전한다. |
| 평행 에지 | 코너 없이 동일한 모형 X축 방향 에지의 참 검출만 유지한다. 많은 카메라가 있어도 랭크 손실이 생기는 경우를 살핀다. |

## 지표의 분모

- 물리 에지 정밀도는 수용된 `(뷰, 모델 ID)` 중 그 ID가 맞은 비율이다. 지지 검사를 제공하는 방법은 최종 지지 뷰가 내보낸 주장만 집계한다. 이 값에는 일부 알고리즘이 별도로 내보내는 추가 후검사 후보가 포함되지 않는다. 조각을 묶으면 구성 조각 모두가 해당 ID여야 하나의 정답이다. 재현율 분모는 하나 이상 참 검출이 있는 `(뷰, 물리 ID)`다. F1은 두 비율의 조화평균이다. `incorrect_association`은 수용된 주장 중 오답의 비율, `fragment_claims`는 묶기 이전 개별 조각 주장 수다.
- 쌍 정확도는 수용된 `(두 뷰, 모델 ID)` 쌍 중 양쪽 주장이 모두 동일한 참 에지인 비율이다. 두 뷰 모두에서 실제 같은 물리 ID가 검출된 쌍을 분모로 하는 쌍 재현율도 제공한다. 여러 쌍이 같은 에지·뷰를 공유한다.
- 가림 복구 분모는 손 가림 때문에 기하 가시성을 잃은 `(뷰, 물리 ID)`다. 나머지 카메라 가운데 하나 이상에서 그 ID를 정확히 주장하면 복구다. 이 분모가 없는 조건의 결과는 공란이다.
- 대응 안정성은 인접 프레임에서 둘 다 참 검출을 할당한 `(뷰, 물리 ID)`에 대해 주장한 모델 ID 집합이 같은 비율이다. 같은 오답도 안정적인 것으로 집계될 수 있으므로 재현율·정밀도와 함께 읽는다.
- 자세 위치는 Euclidean mm, 회전은 SO(3) geodesic °이다. 중앙값·p95·RMSE에는 예측과 유지 자세가 포함된다. 측정이 없고 출력 자세도 없으면 마지막 유효 측정 자세를 오차 계산에만 사용한다. 성공은 **측정**으로 표시하고 20 mm와 8° 이내인 경우다. 오답 측정은 이 기준을 넘긴 유효 측정이며 전체 프레임 및 유효 측정 각각의 분모로 기록한다.
- 재획득 성공은 결함이 끝난 뒤 정확한 유효 측정이 3프레임 연속 이어지는 경우다. 지연은 결함 종료부터 그 연속 구간의 첫 프레임까지이다. 구간 안에서 성공하지 못한 사례는 검열되어 성공률에는 들어가고 시간 백분위에서는 제외한다. 저장된 ms는 실제 센서·연산 지연이 아닌 합성 프레임 간격의 환산값이다.
- 백엔드 시간은 메모리에 준비된 검출부터 자세 반환까지 잰 CPU 벽시계 시간이다. 이 시간에는 데이터 생성·채점·파일 읽기·영상 디코딩이 들어가지 않는다. 각 방법은 한 프레임을 워밍업한다. 단계마다 수집한 대응, 가설, 검증과 재최적화 시간은 해당 구현이 노출하는 경계를 사용한다. Phase II Best의 가설 단계에는 기존 대응·부분집합·진단 계산이 함께 포함된다. 반복 수는 노출된 외부 대응·자세 갱신 단계 수이며 Phase II 내부 Gauss–Newton의 개별 실제 반복 횟수는 수집하지 않았다. 프로세스 peak RSS는 경험 전체의 최대 working set이며 알고리즘 단독 최대 메모리로 해석하지 않는다. 공유 CPU 실행 부하는 통제하지 않았다.

## 재현 명령

Windows 프로젝트 루트에서 `.venv/Scripts/python.exe` 또는 동일한 의존성을 갖춘 `python`으로 실행한다. 모듈 런처가 CPU 1스레드, 3 GiB 프로세스 메모리 커밋 상한과 GPU 비활성 설정을 적용한다. 새 출력 경로를 사용한다.

```powershell
python -B -m evaluation.resource_limits --threads 1 --memory-gib 3 evaluation.pose_benchmark.test_benchmark
foreach ($suite in ('selection','assignment','primary')) {
    python -B -m evaluation.resource_limits --threads 1 --memory-gib 3 evaluation.pose_benchmark.benchmark --suite $suite --output "evaluation/pose_benchmark/replay/$suite"
    if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
}
foreach ($suite in ('recovery','observability')) {
    python -B -m evaluation.resource_limits --threads 1 --memory-gib 3 evaluation.pose_benchmark.benchmark_recovery_cpu --suite $suite --output "evaluation/pose_benchmark/replay/$suite"
    if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
}
```

각 결과 폴더의 `manifest.json`에 설정, 모듈 해시, 실제 실행 범위, NumPy 버전이 남는다. `frames.csv`는 프레임 원자료, `summary.csv`는 방법·배치·활성 기간 단위 집계, `recovery.csv`는 사건별 결과다. 주 결과에 없는 세부 비교는 개발 진단 범위에서 수행한다. [생성 코드](benchmark_data.py) · [실행·채점 코드](benchmark.py) · [주 결과](ABLATION_STUDY.md)
