# 처리율과 지연을 분리해 읽기

실시간 목표에서 필요한 값은 네 영상이 들어온 뒤 응용 프로그램이 언제 해당 시각의 자세를 쓸 수 있는지다. 녹화기는 수신 시각을 기록하므로 노출→수신 지연까지 보고하려면 공통 시각 신호를 추가해야 한다. 한꺼번에 프레임을 처리한 평균 FPS와 개별 프레임의 지연 P95는 별도로 측정한다.

| 입력과 측정 경계 | 결과 | 측정에 포함된 작업 |
|---|---|---|
| 실제 단일 영상 30프레임, 기존 RTX 3060 Laptop 연구 | FP32 전파 중앙값 8.912초, FP16 3.293초 | GPU 상주 상태에서 SAM 전파, 디코딩과 PNG 저장 제외 |
| 같은 영상, 별도 프로세스에서 1회 | FP32 25.919초, FP16 18.890초 | 콜드 모델 로드부터 영상 읽기·전처리·오버레이·출력 저장까지 |
| CPU 합성 검출 192프레임 × 3 | 전체 공동 적합 p50/p95 6.53/10.46 ms, 전체 진단+재적합 35.04/52.68 ms | 이미 검출된 점·선 입력, 동기·분할 제외 |
| Phase IV CPU 실험 | [대응·가설·검증·재적합 시간과 메모리](../../evaluation/pose_benchmark/ABLATION_STUDY.md) | 방법별 실제 계측 경계·비측정 단계와 프레임 수를 표와 함께 확인 |

[GPU 계측 원본](../../evaluation/profiling/results/profile.json) · [CPU 백엔드 원본](../../evaluation/timing/backend_cpu.json)

CPU 전처리 시간을 GPU 전파 중앙값에 단순히 더하면 재현 가능한 종단 측정이 되지 않는다. 병렬 카메라의 큐 대기와 오래된 프레임 폐기, 저장 옵션도 영향을 준다. 실제 실험에서는 같은 세션에서 캡처·동기 그룹 완성·관측 완료·자세 발행 시각을 남기고 드롭 프레임과 지연 분위수를 함께 낸다.

단일 영상에서 초기 SAM 후 LK는 20/30프레임에 마스크를 제공하고 이후 재초기화가 필요했다. 처리 속도만으로 방법을 선택하면 실패 후 개입 비용을 놓친다. Phase III의 AMD OpenCL은 검증된 개별 연산 결과가 있으나 Phase IV는 CPU 기하 연구로 한정됐으며 기존 CUDA/AMD 실험 기록을 보존한다. [경량 추적 실측](../../evaluation/profiling/README.md) · [이전 자원 정책과 범위](../../evaluation/RESOURCE_ISOLATION.md)
