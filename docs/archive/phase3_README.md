# Phase III · 네 번째 카메라의 설치 후보와 물리 모서리 대응

**팀 현장 비교 후보는 상단 (−,+,+)와 (−,−,+)다.** 하단 여유가 실제로 확보되면 (−,+,−)도 비교한다. Z-up 세계에서 정면 카메라는 −Y, 측면은 +X, 상단은 +Z에 있으며 부호는 대각 카메라의 위치를 뜻한다.

| 팀 질문 | 결과와 근거 |
|---|---|
| 여덟 꼭짓점 중 어디가 같은 모서리를 여러 시점에서 가장 많이 보나? | 바닥·기둥을 제외한 실제 꼭짓점 거리에서 (−,+,−)의 동일 모서리 표본 2대 이상 가시율이 96.33%로 가장 높았다. 바닥 여유를 적용한 상단에서는 (−,+,+)가 91.94%였다. [8개 위치 비교표](LAYOUT_COMPARISON.md) |
| 한 대가 빠져도 자세를 구속할 수 있나? | 가능한 네 가지 3대 부분집합 중 최악 조건을 자세별로 구했다. 상단 (−,−,+)는 (−,+,+)보다 최악 부분집합의 최소 고유값 p10이 약간 높았다(578.34 대 572.79). [가시성·정보행렬·누락 결과](layout_geometry/README.md) |
| 한 영상에서 가려진 물리 모서리를 나머지 영상이 정확히 찾아주는가? | 동일한 축 카메라 손실 85건 중 A가 62건, B가 68건에서 다른 시점의 동일 물리 ID를 맞혔다. 손·궤적·검출 잡음과 초기 자세는 합성 조건이다. [대응·자세·P95·실패율](layout_pose/README.md) |
| 매칭된 선이 정말 그 모서리인가? | 네 대표 배치의 336프레임에서 추정 후 수직 잔차·방향·겹침을 검사했다. B에서 ID 쌍 정밀도는 68.22%에서 98.15%로 증가하고 쌍 재현율은 74.30%에서 68.25%로 감소했다. 같은 프레임으로 적합한 자세를 사용한 후검사이며 원래 자세 추정에는 피드백하지 않았다. [분모·제외 시점 검증·원시 카운트](edge_identity/README.md) |
| 현장에서 무엇으로 결정을 내리나? | 실제 바닥·기둥·케이블 간섭, 도달 가능한 보드 각도, 손 접근 방향, 실측 물리 ID·P95 오차와 팀 의견을 기록한다. [마운트·보정 검증 절차](MOUNT_VALIDATION.md) |

### 보존한 가속 실험

AMD 추가 실행은 2026-11-26 사용자 요청으로 중단했다. 아래는 중단 전에 기록된 결과다.

- [OpenCV 연산별 CPU/680M 비교](amd/opencl/README.md)와 [실영상 30프레임 전체 관측 경로](amd/opencl/observations/README.md). 후자에서 선분 채택과 코너 134개가 일치했다.
- [작은 모델의 명시적 AMD ONNX 추론](amd/results/fusion_inference.json), [CPU 학습 및 DirectML 경로 상태](amd/results/fusion_train.json), [별도 AMD OpenCL 학습 로그](amd/opencl_learning/measured.json). OpenCL 구현과 PyTorch DirectML은 서로 다른 실행 경로다. PyTorch DirectML의 장치 확인 단계가 보호 조건에 걸려 학습 성공으로 집계하지 않았다.
- SAM 2 전체 AMD 이식이나 부분 모듈 최종 측정은 확인된 결과 파일이 없어 미검증으로 남겼다. 기존 RTX 측정은 [Phase II 프로파일](../phase2/profiling/README.md)에 있다. [프로세스 장치 선택과 자원 제한](RESOURCE_ISOLATION.md)
